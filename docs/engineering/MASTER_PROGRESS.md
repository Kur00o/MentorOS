## What was built

### Backend (`backend/app`)
- **Model** — 27 tables with provenance (`data_batches`, `is_synthetic`), CHECK/unique constraints, autogenerated Alembic baseline run under an advisory lock.
- **Auth & permissions** — Supabase JWT verification (HS256 / JWKS / Auth-API fallback), identity linked to admin-provisioned users on first sign-in, roles from the DB only, scope helpers (`core/deps.py`) used by every router, 404 for out-of-scope records.
- **Scoring** — one pure formula (`scoring/formula.py`); bulk engine (a few queries for any cohort size) that appends history, mirrors the latest score, and runs eight explainable, self-resolving risk rules.
- **Workflows** — Student 360, profile/placement/resume/avatar, DPDP consent (under-18 + wellness locks), meetings (request → confirm → log → action items; clash detection; no-show), alerts (acknowledge/resolve with notes), allocation (risk-first heap engine, dry-run preview, manual reassignment with history, capacity), HOD and institution analytics, CSV imports with row-level errors, connector sync, NAAC/students/at-risk/audit exports, notifications, audit log.
- **Companion** — grounded, role-scoped answers + BM25 knowledge base; optional Anthropic/OpenAI/Gemini/Ollama voice.
- **Ops** — protected bootstrap endpoints, Vercel Cron nightly recompute, health/readiness with deployed commit.

### Frontend (`frontend/src`)
- Design system “field instrument”: paper/night-shift tokens, Fraunces + Hanken Grotesk + Martian Mono, sheet depth and grain, Motion choreography, Radix primitives.
- Signature **Signal Trace** (seismograph drawn by a pen nib over band zones with meeting marks and read-off crosshair), sprung **gauge**, micro-traces, cohort strata, heatmap, histogram, funnel.
- 26 screens across the four desks, companion panel, ⌘K palette, notifications, mobile tab bar, route-level code splitting.

### Data
- Deterministic generator (`backend/app/seed/generator.py`): 3 departments, 10 mentors + 3 HODs + 2 admins, 150 students from behavioural archetypes, 60 subjects, 18 weeks of attendance and LMS activity, internals, semester results, placement profiles/offers, ~320 meetings with logs and action items, allocations, consents, notifications. Scores and alerts are computed by the real engine.

## Known limitations & next steps

1. **Google OAuth** needs the Google provider configured in the Supabase dashboard (client ID/secret), then `GOOGLE_OAUTH_ENABLED=true` and `VITE_ENABLE_GOOGLE_AUTH=true`.
2. **LLM** — no provider key is configured; the companion runs in grounded mode. Add `ANTHROPIC_API_KEY` (or another provider) in Vercel to enable the conversational voice.
3. **Email/webhook** delivery not configured; notifications are in-app.
4. **Git-connected deploys** — the Vercel project is deployed via CLI; connect it to `Kur00o/MentorOS` in Vercel for automatic deploys on push to `main`.
5. **Custom domain** — `mentoros.vercel.app` was taken; production alias is `mentoros-murex.vercel.app`.
6. **Shared demo** — anyone with the demo password can modify synthetic records (purge and demo-account deactivation are blocked). Re-seed with `POST /api/v1/ops/bootstrap/seed?force=true`.
7. Before real data: follow “Going live with real data” in `DEPLOYMENT.md`.
